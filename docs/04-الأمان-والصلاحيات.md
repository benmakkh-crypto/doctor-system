# الأمان والصلاحيات

**المبدأ:** الواجهة لا تملك أي سلطة. كل طلب يصل الخادم يمر بست بوابات بالترتيب، وأي بوابة ترفض تُنهي الطلب برسالة واضحة دون تغيير شيء.

```
1. الجلسة     ← رمز صالح غير منتهٍ، وحساب نشط
2. كلمة المرور ← إن كانت مؤقتة لا يُسمح إلا بتغييرها
3. الدور       ← المشاهد لا يكتب، وإجراءات المسؤول للمسؤول
4. الإدارة     ← المستخدم المحصور لا يلمس غير إداراته
5. المدخلات   ← نوع وطول وصيغة وقائمة وتفرد
6. القفل       ← الكتابة على أحدث نسخة، وكتابة سطر التدقيق
```

## ما لا يحميه النظام (مسؤولية الجمعية)

1. **حساب Google المالك.** يملك الجدول ويستطيع تعديله مباشرة. استخدم حسابًا مؤسسيًا مخصصًا بمصادقة ثنائية، ولا تشارك الجدول ولا مجلد Drive مع أحد.
2. **تسليم كلمات المرور المؤقتة.** سلّمها شخصيًا أو عبر قناة خاصة، لا في مجموعة واتساب.
3. **الأجهزة المشتركة.** لا تُستخدم «تذكرني» عليها، ويجب تسجيل الخروج دائمًا.
4. **محرر Apps Script.** من يُمنح صلاحية تحرير المشروع يستطيع تغيير الشيفرة. لا تمنحها لغير المسؤول التقني.

## نظام حماية البيانات الشخصية (السعودية)

يعالج النظام بيانات شخصية: الهوية، والجوال، وعدد أفراد الأسرة، والإعانات. ولمواءمته مع نظام حماية البيانات الشخصية:

- **الضرورة:** لا تُجمع إلا الحقول المعرّفة، وكل حقل حساس اختياري ما عدا ما تطلبه الإجراءات.
- **الحد من الوصول:** حصر الإدارات، وإخفاء جزئي للمشاهد.
- **السجل:** كل اطلاع على مرفق وكل تعديل مسجّل باسم المستخدم ووقته.
- **الاحتفاظ:** تُحذف النسخ الاحتياطية الأقدم من 14 يومًا تلقائيًا.
- **مطلوب من الجمعية:** سياسة خصوصية معلنة، وموافقة المستفيد على جمع بياناته، وتحديد مدة الاحتفاظ بالملفات المغلقة.

هذا ليس رأيًا قانونيًا؛ راجعوا مستشاركم القانوني قبل التشغيل.
